# DeckRef 角色记忆与使用说明

本文档是**各专项角色 Agent 的「记忆」入口**：每个角色负责什么、涉及哪些模块、近期做过什么。新开对话并指定「你是 XXX 角色」时，让 Agent 先读本文档中对应小节 + `CHANGELOG.md` 最近几条，即可在长时间开发后仍能接上上下文。

---

## 一、为什么用「文档」做记忆（Cursor 机制简述）

- **Cursor 没有跨对话的持久记忆**：每个 Chat 的上下文有上限，旧消息会被裁剪或无法被新对话访问。
- **agent-transcripts 只是存档**：历史对话以 .jsonl 形式保存，不会自动注入到新对话；新开一个 Chat 时，模型看不到别的 Chat 的内容。
- **可靠做法**：把「谁负责什么、最近做了什么」写进**仓库里的文档**，任何新对话通过 **@ 引用该文档** 即可加载这段「记忆」。安全（不复制大段代码、不存敏感信息）、可维护（和 CHANGELOG/留痕流程一致）、不依赖 Cursor 是否提供「记忆」功能。

---

## 二、使用方式（如何让 Agent 加载记忆）

1. **新开对话并指定角色时**，在首条消息中写清楚角色并指向本文档，例如：  
   「你是**易用性功能开发者**，请先看 @docs/AGENT_ROLES.md 里你的部分，以及 @CHANGELOG.md 最近几条，再接下去做 XXX。」
2. **可选**：在 Cursor 规则中已配置「当用户指定为下列角色之一时，先阅读 docs/AGENT_ROLES.md 中对应角色小节」，Agent 会自动带入该段记忆（若规则被命中）。
3. **维护记忆**：该角色完成功能或重要修复后，除按现有流程更新 CHANGELOG 与相关 doc 外，在本文档**对应角色**的「近期完成」中补一行简述或引用 CHANGELOG 日期/条目，使「记忆」与事实同步。

## 三、各角色小节（记忆内容）

以下按角色列出：职责、主要涉及模块、近期完成（会随开发更新，请以 CHANGELOG 为准）。

### 1. 基础功能开发者

- **职责**：核心功能与交互、项目骨架、修 bug、稳定性；保证交互符合直觉、模块化与错误处理规范。
- **涉及模块**：`src/app.rs`、`src/image_card.rs`、`src/lib.rs`、`src/main.rs`、`docs/INTERACTIONS.md`。
- **近期完成**：项目从零搭建（eframe + notify + image）；长按拿起/放下、堆叠与排序、物理感交互；窗口抖动与底边栏/一览按钮随窗口移动的修复；拖放与拖出、防止循环保存、启动异步加载、模式切换与缓存等。**剪贴板截图误存 QQ 群图 bug 修复**：仅当按下 Shift 后约 5 秒内才保存剪贴板截图，避免误存 QQ/浏览器复制的图。详见 CHANGELOG 2025-03-02～03-04。
- **相关对话**（可选追溯）：agent-transcripts 中 `1d61b303`（项目骨架）、`735c2d81`（拿起放下交互）、`424831c9`（抖动与底栏修复）。

### 2. 代码提交者

- **职责**：Git 与 GitHub 维护、推送前预审、分支与提交规范；不提交敏感信息、不 force push（除非明确要求）。
- **涉及**：`docs/GITHUB_SUBMISSION.md`、`.gitignore`、CHANGELOG、仓库与认证配置。
- **近期完成**：建立私人仓库与首次推送；提交预审规范（含 `cargo test`、安全与留痕）；README、.gitignore 完善。详见 CHANGELOG 与 `docs/GITHUB_SUBMISSION.md`。
- **相关对话**：agent-transcripts 中 `f5641310`（GitHub 维护与上传）。

## 四、维护约定

- **谁更新**：该角色完成功能或重要修复后，由该对话中的 Agent 或你在提交前，在本文档对应角色的「近期完成」中补一行（或引用 CHANGELOG 日期），保持与 CHANGELOG 一致。
- **不放入记忆的内容**：不粘贴大段代码；不写密钥、路径等敏感信息；详细实现以代码与 CHANGELOG 为准，本文档只做摘要与索引。
- **与 CHANGELOG 的关系**：CHANGELOG 是权威的「做了什么」记录；本文档的「近期完成」用于快速唤醒该角色的上下文，可写「见 CHANGELOG YYYY-MM-DD」或一行简述。

*文档版本：随开发更新；各角色「近期完成」请以 CHANGELOG 与代码为准。*
