# 提交代码到 GitHub 的 Agent 规范

**适用对象**：任何执行「将本仓库代码提交/推送到 GitHub」的 Agent。  
**强制要求**：在执行任何 `git commit`（意图保留到历史）或 `git push` 之前，**必须**完成本文档规定的预审与步骤，否则不得提交/推送。

---

## 一、预审义务（必须全部通过才可提交）

提交前，Agent **必须**自行完成以下预审，并在对话中给出结论（通过 / 不通过 + 理由）。

### 1. 代码安全

- [ ] **无敏感信息**：本次变更中**未**包含密钥、API Key、密码、Token、.env 内容、真实用户数据等；未将上述内容写入代码或文档。
- [ ] **无危险命令或逻辑**：未引入未受控的 `std::process::Command` 执行外部命令、未引入从网络拉取并执行的代码、未引入明显恶意或破坏性逻辑（如删除用户目录、格式化磁盘等）。
- [ ] **路径与 IO**：文件读写基于用户指定或应用配置的路径，无硬编码绝对路径指向系统关键目录；监听/扫描目录范围受控（如本项目仅监听用户指定的图片目录）。
- [ ] **依赖**：未添加来源不明或未审核的第三方 crate；若新增依赖，已确认来自 crates.io 且非恶意包。

### 2. 与项目规范一致

- [ ] **交互**：若本次变更涉及交互（鼠标、滚轮、按钮、触控），已对照 `docs/INTERACTIONS.md` 检查，且**已同步更新**该文档，使文档与代码一致。
- [ ] **留痕**：本次变更若包含新功能或重要修复，已在 `CHANGELOG.md` 的「未发布」小节中追加一条（日期 + 简述 + 涉及文件/模块）。
- [ ] **构建**：在项目根目录执行 `cargo build`（或 `cargo build --release`）**通过**，无编译错误。
- [ ] **静态检查**：执行 `cargo clippy`（若项目配置了 clippy）无新增 warning；若存在既有 warning，本次变更未加重且已说明。

### 3. 提交内容与范围

- [ ] **仅提交约定范围**：仅包含与本次功能/修复相关的源文件与文档变更；未将构建产物（如 `target/`）、本地配置、IDE 私有文件、临时文件提交进仓库。
- [ ] **提交信息**：每条 commit 信息清晰、可读，能概括本 commit 的改动目的（建议一行摘要 + 可选多行说明）；不提交空 commit 或无意义信息。

---

## 二、禁止行为（出现则不得提交）

- **禁止**在未通过上述预审的情况下执行 `git push` 或等效的「将代码推送到远程」操作。
- **禁止**使用 `git push --force`（或 `-f`）覆盖远程已有历史，除非用户**明确**要求并知晓风险。
- **禁止**将 `.env`、`*.pem`、含密钥的配置文件、或任何包含真实凭据的文件加入版本库。
- **禁止**在预审未完成或预审不通过时，以「先提交再修」为由执行推送。

---

## 三、推荐流程（提交到 GitHub 时的执行顺序）

1. **确认范围**：用 `git status` / `git diff` 确认本次将要提交的文件与改动符合预期，无多余或敏感文件。
2. **执行预审**：按「一、预审义务」逐项检查，在对话中列出结果（可简要写「安全/规范/构建/范围：通过」或某项不通过及原因）。
3. **构建与检查**：在项目根目录执行 `cargo build`（及可选 `cargo clippy`），确认通过。
4. **留痕**：若为功能/重要修复，确保 `CHANGELOG.md` 已更新；若为交互改动，确保 `docs/INTERACTIONS.md` 已更新。
5. **提交**：`git add` 仅包含约定范围的文件，`git commit` 使用清晰信息。
6. **推送**：在用户确认或明确要求推送时，执行 `git push`（非 force）。

若用户仅要求「预审」而不要求立即推送，则完成步骤 1～4 并汇报预审结果即可，不执行 5、6。

---

## 四、预审不通过时的汇报格式

当任一项预审不通过时，**必须**在对话中明确说明，并**不得**执行提交/推送。汇报应包含：

- 不通过项（如「代码安全 - 敏感信息」）；
- 简要理由（如「某文件包含 API Key」）；
- 建议修复方式（如「移除该 Key 或改为从环境变量读取」）。

待用户或开发 Agent 修复后，重新执行预审流程。

---

## 五、与本仓库其他文档的关系

- **AGENTS.md**：总入口；提交 Agent 也需知晓项目结构与必读文档。
- **docs/INTERACTIONS.md**：交互单一来源；涉及交互的变更必须与此文档一致并同步更新。
- **CHANGELOG.md**：功能与重要修复的留痕；新功能/重要修复必须在提交前在此留痕。
- **.cursor/rules**：项目通用约定（先查文档、改完留痕）仍然适用；本文档在「提交到 GitHub」场景下增加**预审与安全**的强制要求。

---

*本文档为「提交代码到 GitHub 的 Agent」的强制规范，预审未通过不得提交/推送。*
