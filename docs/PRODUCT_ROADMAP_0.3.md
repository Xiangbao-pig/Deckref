# DeckRef 产品对比分析与 0.3.0 规划草案

**角色**：产品视角（参考成熟画板/参考图产品）  
**目的**：为 0.3.0 及后续版本的功能合理性、易用性与优先级提供依据，并与你一起敲定下个版本要做哪几件重要功能。

---

## 一、产品定位对比

| 维度 | DeckRef（当前） | PureRef | Figma | Miro |
|------|-----------------|---------|-------|------|
| **核心场景** | 图片堆叠浏览 + 快捷抓图，目录即画布 | 参考图/灵感板，单画布可存可导 | UI/UX 设计、原型、交付 | 无限白板、头脑风暴、协作工作坊 |
| **画布模型** | 单画布 = 当前监听目录，切换目录即换内容 | 单画布 .pur 文件，可多窗口多画布 | 文件 → 页 → Frame，网格+向量 | 单板无限画布，多板 |
| **内容形态** | 以图片为主，来自文件夹/拖入/剪贴板 | 图片 + 分组 + 富文本笔记 + 手绘 | 矢量、组件、原型、评论 | 便签、形状、图片、视频、模板 |
| **协作** | 本地单机 | 本地单机（2.0 无实时协作） | 强协作（评论、多人、Dev Mode） | 强协作（投票、计时、研讨会） |
| **与 DeckRef 相关性** | — | **高**：同属「艺术家/创作者参考图」 | **中**：画布与组织方式可借鉴 | **中**：无限画布、便签思路可借鉴 |

**结论**：DeckRef 与 PureRef 的定位最接近（本地、以图为主、艺术家/创作者）；Figma/Miro 更偏协作与「设计/白板」工具，但画布组织、分组、导出等思路可选择性借鉴。

---

## 二、功能差距与机会点（对标 PureRef 与通用画板）

### 2.1 DeckRef 已有、且与参考产品对齐的能力

- 监听目录 + 拖入即存 + 剪贴板粘贴（快捷抓图）
- 堆叠 + 拿起/放下 + 视图缩放/平移 + 单卡缩放
- 一览打散 + 阵列紧密排列（类似「网格整理」）
- 双模式（默认文件夹 / 灵感最近+截图）
- 地址栏、最近到访、后退前进、设置持久化

### 2.2 参考产品有、DeckRef 暂无且值得考虑的能力

| 能力 | PureRef | Figma/Miro 类似 | 对 DeckRef 的价值 | 实现复杂度（粗估） |
|------|---------|-----------------|--------------------|--------------------|
| **画布布局持久化** | .pur 存位置/缩放/分组 | 文件即画布状态 | 换目录或重启后「摆好的样子」不丢，核心体验 | 高（需独立于「当前目录」的布局存储） |
| **分组（Group）** | 多图+笔记成组，一起移动 | Frame/Group | 参考图按项目/镜头分组，减少杂乱 | 中 |
| **简单笔记/便签** | 富文本笔记 | 便签、文本 | 在画布上记要点、标注，不依赖外部工具 | 中（若只要纯文本+位置则相对简单） |
| **始终置顶 / 贴边** | 可钉在特定应用之上 | — | 一边画图一边看参考，不挡主软件 | 中（系统级窗口行为） |
| **导出/快照** | 导出为图或 PDF | 导出 PNG/PDF | 分享当前画布视图或交付物 | 中低 |
| **多画布/多板** | 多窗口多文件 | 多页/多板 | 多项目或多镜头分开摆 | 高（需抽象「板」与「当前目录」关系） |
| **手绘/标注** | 简单画笔、箭头、直线 | 画笔、形状 | 在参考图上圈注，沟通或自查 | 中高（渲染与交互） |
| **命令面板 / 快捷键** | 快速执行命令 | 全局搜索/命令 | 提升熟练用户效率 | 低～中 |

### 2.3 优先级与合理性（产品视角）

- **画布布局持久化**：与「符合艺术家直觉」「摆参考图、看图、比对」直接相关，换目录或重启后布局丢失是当前最大体验缺口；**合理性高，建议作为 0.3.0 的核心目标之一**。
- **分组（Group）**：显著提升「多图归类、一起移动」的易用性，与 PureRef 核心场景一致；**合理性高，优先级可紧随布局持久化**。
- **简单笔记/便签**：能减少在画布与外部笔记间切换，但若 0.3.0 资源有限，可先做「分组 + 布局持久化」，笔记放在 0.4.0；**合理性高，优先级中**。
- **始终置顶 / 贴边**：对「一边用主软件一边看参考」的场景价值大，实现相对独立；**合理性高，可作为 0.3.0 的「体验增强」项**。
- **导出/快照**：分享与交付的闭环，**合理性高，优先级中**（可与 0.3 或 0.4 一起规划）。
- **多画布/多板**：需求强但会牵涉数据模型与 UI 较大改动，**更适合作为 0.4.0 或更晚的主题**。
- **手绘/标注**：差异化强，但实现与测试成本高，**建议 0.4.0 再评估**。
- **命令面板/快捷键**：投入小、收益明确，**可作为 0.3.0 的「小但亮」的改进**。

## 三、0.3.0 已定范围与开发阶段（敏捷 Phase 1/2/3）

### 3.1 0.3.0 主题与目标（已拍板）

**主题**：**「画板模式 + 分组 + 快速选文件夹」**  
**目标**：新增第三模式「画板」，画布布局持久化；支持框选与分组（成组移动/缩放）；TAB 呼出文件夹树面板便于快速切换目录。布局粒度当前采用「每目录一份布局」，多画布/多板留到以后。**便签/笔记**明确放在 **0.4.0** 及以后。敏捷开发，只划分 Phase 1/2/3，不绑定具体日历时间。

**可维护性与扩展性**

- **菜单结构**：上下文菜单由**菜单项列表**驱动构建（如枚举或配置列表），每项包含：id、显示文案、是否可用、执行回调。新增功能时仅增加新项并实现对应逻辑，不修改菜单弹出与事件分发框架。
- **模式区分**：若某菜单项仅在某模式可用（如「加入组/从组移除」仅画板模式），在构建列表时按当前模式过滤即可，便于后续按模式或权限扩展。
- **文档**：新增或变更菜单项时同步更新 `INTERACTIONS.md` 与本文 3.2.1。

### 3.3.1 Phase 2：成组与取消分组详细逻辑（参考 PureRef / Miro）

以下约定**成组（Group）**与**取消分组（Ungroup）**的交互、数据与持久化，对齐 PureRef 与 Miro 的成熟方案，便于实现与后续扩展。

---

**一、创建组（成组）**

| 项目 | 约定 | 参考 |
|------|------|------|
| **触发** | 当前有**多张卡片被选中**时，通过**快捷键**（如 Ctrl+G / ⌘G）或**菜单/右键**「成组」创建组。仅选一张或未选时，「成组」不可用或灰显。 | PureRef：Images > Selection > Group（Ctrl+G）；Miro：选中多对象后 Ctrl+G。 |
| **结果** | 选中的卡片归入**一个新组**；组在画布上表现为一个**整体**，拥有共同的边界框（AABB），组内卡片保持**相对组的相对位置与缩放**不变。 | 两组均：成组后作为单一体移动/变换。 |
| **组与堆叠** | 组在画布上占一个「逻辑层」：组整体参与堆叠顺序（可与未分组卡片、其他组一起置顶/移后）；组内卡片之间的前后顺序在组内维护。 | PureRef：Hierarchy 中 parent/child；Miro：组内仍可双击编辑单对象。 |
| **空组** | 若取消分组后某组内已无任何卡片，**自动删除该组**，不保留空组。 | PureRef：empty groups automatically deleted。 |

---

**二、组的移动与缩放**

| 项目 | 约定 | 参考 |
|------|------|------|
| **整体移动** | **选中组**（点击组内任意卡片或组背景/边框时，若当前策略为「选组」则选中整个组）后，拖拽 = 整组平移；组内每张卡片的**画布绝对位置**同向同距移动，**相对位置**不变。 | PureRef / Miro：move group = move all children。 |
| **整体缩放** | 选中组后，若支持**组级缩放**（如拖拽组边界手柄或滚轮）：以组中心（或用户可选锚点）为原点，组内每张卡片的**位置与 display_scale** 按同一比例缩放，使组作为一体放大/缩小。0.3.0 可简化为：仅支持**组整体移动**，组内单卡缩放仍通过「选中单卡后滚轮」；组级缩放可后续版本再上。 | Miro：selected objects 可一起 resize；PureRef：group 可 transform as single unit。 |
| **组内单卡** | 用户需要**只移动或只缩放组内某一张卡**时：通过「进入组」或「直接点选组内卡」实现（见下条「选中与进入组」）。 | Miro：double-click and drag to move one object within group。 |

---

**三、选中与「进入组」**

| 项目 | 约定 | 参考 |
|------|------|------|
| **默认：选组** | 点击组内任意一张卡片或组区域时，若该卡属于某组，**默认选中整个组**（高亮组边界或组内全部卡片），便于整组移动。 | PureRef：默认 "locked" 组，点组内 = 选组。 |
| **进入组 / 选组内** | **双击**组内某张卡片（或组区域）时，进入「组内选择」状态：后续点击/框选仅在该组内生效，可选中单张或多张组内卡进行移动或缩放；**单击组外空白**或按 **Esc** 退出组内选择，回到「选组」语义。 | PureRef：double-click item to enter group；Miro：double-click to edit one object in group。 |
| **可选：锁定模式** | 与 PureRef 一致的可选策略：组可设为「锁定」— 锁定后点击组内一律选组，只有双击进入组内后才能选单卡。0.3.0 可先实现「点击组内 = 选组、双击 = 进入组内」，不做单独的锁定开关。 | PureRef：Toggle locked；default new groups locked。 |

---

**四、向组内添加 / 从组移除**

| 项目 | 约定 | 参考 |
|------|------|------|
| **向组内添加** | ① **拖拽**：将一张**未分组**的卡片拖拽到已有组的**区域**（组 AABB 内或组边界附近）松手，则该卡加入该组（写入组的成员列表，位置为松手时的画布位置或相对组的相对位置）。② **菜单**：多选时包含「已选中的组」与「若干未分组卡」时，提供「加入组」：将当前选中的未分组卡加入选中的组。 | PureRef：drag items into group；右键「加入组」。 |
| **从组移除** | **取消分组**：选中**一个组**或**组内部分卡片**时，通过**快捷键**（如 Ctrl+Shift+G / ⇧⌘G）或**菜单/右键**「取消分组」。① 若选中**整组**：组解散，组内所有卡片变为未分组，**画布上的位置与缩放保持不变**。② 若选中**组内部分卡片**：仅将这些卡片从组中移除，变为未分组；组内其余卡片仍保留在原组；若组内所剩卡片为 0，则自动删除组。 | PureRef：Ungroup（Ctrl+Shift+G）；select items and ungroup。Miro：select group → ungroup icon。 |

**五、取消分组（整组解散）**

| 项目 | 约定 | 参考 |
|------|------|------|
| **触发** | 选中一个或多个组（或组内全部/部分成员）后，快捷键 **Ctrl+Shift+G**（或 ⌘+Shift+G）或菜单/右键「取消分组」。 | PureRef：Images > Selection > Ungroup；Miro：select grouped objects → ungroup。 |

**六、持久化（布局存储）**

| 项目 | 约定 |
|------|------|
| **组结构** | 在 `.deckref_layout.json` 中为每个组分配**唯一 id**（如 `group_id`）；每张卡片若属于某组，则记录 `group_id`；组内卡片的**顺序**用数组顺序或显式 `order_in_group` 表示，用于绘制顺序与「置顶/移后」语义。 |

**七、与框选、拿起、右键的优先级**

- **空白处拖拽** → 框选（多选）；若未拖到任何卡片则取消当前选择（或仅取消多选）。
- **点击组内** → 选中组（或进入组内，见上）；**长按组内某卡** → 若当前为「组内选择」则可能拿起该卡，若当前为「选组」则保持选组或进入组内（可约定长按组内 = 进入组内后再参与拿起逻辑）。
- **右键组内** → 弹出上下文菜单；若为整组选中则菜单含「取消分组」等组操作；若为组内单卡则含「从组移除」等。

### 3.4 画板布局存储方案（方案 B）与卸载时安全清理

**方案 B：布局文件放在文件夹内（sidecar）**

- **文件名**：**`.deckref_layout.json`**（放在当前监听目录内，建议以隐藏文件形式存在，减少对用户的视觉干扰）。
- **内容**：当前画布的卡片位置、缩放、顺序及 Phase 2 的分组信息等，JSON 格式。
- **读写**：进入画板模式并选定某目录时，若该目录下存在 `.deckref_layout.json` 则加载，否则视为新画布；退出、切换目录或定时/防抖时将当前布局写回该目录下的此文件。
- **移动/复制文件夹**：用户**移动或复制**该文件夹时，sidecar 会随文件夹一起移动或复制，在新路径下打开该目录时仍能加载同一份布局，**无需额外逻辑即可支持「新路径下复原布局」**。

**卸载时安全清理画板布局文件**

- 为避免卸载后在用户各目录中遗留 `.deckref_layout.json`，同时**不影响用户正常使用**（只删除我们创建过的文件、不误删用户数据），采用**登记制 + 卸载时可选清理**：
  - **登记**：每次成功向某目录写入 `.deckref_layout.json` 时，将该目录的**规范路径**（如 `canonicalize` 后的绝对路径）**追加**到配置目录下的 **`layout_dirs.txt`**（每行一个路径，去重可选）。
  - **卸载时**：在卸载流程（如 Windows 的 Uninstall.bat 或 MSI 卸载程序）中提供**可选步骤**：「是否删除已保存的画板布局文件（.deckref_layout.json）？」若用户选择是，则**仅**读取 `layout_dirs.txt`，逐行取路径，在该路径下删除 **`.deckref_layout.json`**；若路径已不存在（用户已移动/删除文件夹）则跳过；不修改目录内其他文件。
  - 这样仅会删除我们曾写入过的目录中的布局文件，**不会影响用户未使用过画板功能的目录**，也不会误删用户自己的文件；用户选择「否」时保留所有布局文件，重装后仍可继续使用。

**与现有卸载脚本的衔接**

- Windows 现有 **Uninstall.bat**（或 MSI 卸载）在「是否清理 DeckRef 产生的缓存」之外，可增加一档：「是否删除各文件夹内的画板布局文件（.deckref_layout.json）？」若选是，则执行上述基于 `layout_dirs.txt` 的删除逻辑（需在卸载前从配置目录读取该文件）。配置目录 `%APPDATA%\DeckRef` 下的 `layout_dirs.txt` 本身可在「清理配置与数据」时一并删除。
