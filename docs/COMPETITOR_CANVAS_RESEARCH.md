# 竞品窗口与画布调研报告

本报告对 **Chrome**、**Photoshop**、**Miro**、**PureRef** 四款产品在**画布空间（Canvas Space）**与**屏幕空间（Screen Space）**的划分，以及**缩放视图（Zoom）**、**多选/单卡缩放（Transform）**、**调整窗口（Resize）**的逻辑进行梳理，供 DeckRef 窗口与画布交互设计参考。

---

## 一、Chrome（浏览器）

### 1.1 画布空间 vs 屏幕空间

Chrome（Blink）明确区分多种坐标空间，与「画布/屏幕」的对应关系大致如下：

| 概念 | 含义 | 对应关系 |
|------|------|----------|
| **Screen / Visual Viewport** | 设备无关像素（DIP），相对浏览器窗口左上角；包含 pinch-zoom 后的「可见区域」 | 接近**屏幕空间**：用户实际看到的区域 |
| **Layout Viewport** | 未缩放时的 CSS 像素，作为整页布局与 `position: fixed` 的参考；**不随 pinch-zoom 改变** | 接近**画布/文档的布局基准** |
| **Frame / Client** | 未缩放 CSS 像素，含滚动偏移，等价于 JS 的 client 坐标 | 文档在「当前帧」内的坐标 |
| **Document Content** | 未缩放 CSS 像素，整页内容，等价于 page 坐标 | **画布空间**（文档内容） |

要点：

- **画布空间**：文档内容坐标系（page / document），单位是未缩放的 CSS 像素，随页面内容与滚动变化。
- **屏幕空间**：Visual Viewport 的宽高与位置（`visualViewport.width/height`、`pageLeft/pageTop`），以及 `scale`（pinch 缩放倍率）；鼠标坐标需结合 viewport 与 scale 换算到文档坐标。
- **两种 Zoom**：  
  - **Browser Zoom（页面缩放）**：改变 CSS 像素与 DIP 的比例，会触发重排。  
  - **Pinch-Zoom（页面缩放）**：只缩放渲染表面，不重排；Visual Viewport 的 `scale` 会变化，Layout Viewport 不变。

### 1.2 缩放视图（Zoom）

- **方式**：Ctrl/Cmd + 加减、pinch、地址栏缩放等。
- **行为**：  
  - Pinch-zoom 时 **Visual Viewport 缩小/放大**，Layout Viewport 不变；`visualViewport.scale` 反映当前缩放。  
  - 缩放中心由手势/UI 决定，通常以焦点或手势中心为准。
- **坐标换算**：Canvas 等元素在应用自身 scale/transform 时，需用 `getBoundingClientRect()`、`visualViewport.offsetLeft/offsetTop` 与 `scale` 将鼠标位置换算到画布逻辑坐标。

### 1.3 多选/单卡缩放（Transform）

- 浏览器本身不提供「画布内对象多选缩放」的通用语义；页面内由具体 Web 应用（如 Miro、Figma）自行实现。
- 若页面内嵌 Canvas/SVG，其内部对象的 Transform 由应用维护逻辑坐标与变换矩阵，再映射到屏幕。

### 1.4 调整窗口（Resize）

- **Layout Viewport**：由窗口尺寸与 chrome UI 决定，窗口 Resize 会改变 layout viewport 尺寸。
- **Visual Viewport**：Chrome 61+ 提供 `window.visualViewport`；`resize` 在 width/height/scale 变化时触发，`scroll` 在 offset 变化时触发。
- **平台差异**：  
  - 桌面：窗口 Resize 会同时影响 layout 与 visual viewport 的尺寸。  
  - 移动端（如 Android）：Chrome 108 起，软键盘弹出时只改变 **Visual Viewport**，不改变 Layout Viewport，与 iOS 行为一致。

## 二、Photoshop

### 2.1 画布空间 vs 屏幕空间

- **画布空间（文档空间）**：  
  - 文档的像素网格（图像尺寸），坐标以画布左上或中心为参考；图层、选区、参考线等都在此空间。  
  - 与「文档窗口」独立：同一文档可多窗口查看，每个窗口有自己的视图状态（缩放、平移）。
- **屏幕空间**：  
  - 文档窗口内可见区域，即「当前视图」在屏幕上的投影。  
  - 由「缩放比例 + 平移」决定：画布上哪一块、以多大倍率显示在窗口内。

关系可以概括为：**屏幕所见 = 画布空间的一个矩形区域 × 缩放倍率**，平移决定该矩形在画布上的位置。

### 2.2 缩放视图（Zoom）

- **操作**：  
  - 缩放工具（Z）：点击放大、拖拽框选区域放大、双击 100%。  
  - **Scrubby Zoom**：在选项栏开启后，Z + 左右拖拽即可缩放（右放大、左缩小），以拖拽区域为中心。  
  - Alt/Option + 滚轮：需在「首选项 > 常规」中开启「滚轮缩放」。  
  - Ctrl/Cmd + +/-、Ctrl+0 适应屏幕、Ctrl+1 实际像素（100%）。
- **行为**：  
  - 缩放以**点击位置或拖拽中心**为基准，使该点在屏幕上的位置尽量保持稳定（与 DeckRef「以指针为中心」类似）。  
  - 当画布在 100% 时能完整放入窗口，Photoshop 会**锁定居中且禁止平移**；超过 100% 才可自由平移。
- **多窗口**：可勾选「缩放所有窗口」，使多窗口同步缩放比例。

### 2.3 多选/单卡缩放（Transform）

- **多选变换**：多图层同时选中后，使用自由变换（Ctrl/Cmd+T）会**共用一个变换框**，多对象作为**一个整体**缩放/旋转，间距同比变化；无「按各自中心分别缩放」的官方功能。  
- **单层缩放**：自由变换下可拖动手柄缩放，可切换参考点（左上/中心等）；数值栏可输入精确比例。  
- **画布本身**：画布尺寸通过「图像 > 画布大小」修改，不属于图层的 Transform。

### 2.4 调整窗口（Resize）

- **文档窗口**：拖拽边缘/角可调整窗口大小；内容区随之变大变小。  
- **选项「缩放时调整窗口大小」**：若开启，使用缩放工具改变倍率时，会**同时调整文档窗口**以适配新缩放，避免出现大量留白或裁剪感。  
- **视图与画布关系**：Resize 窗口只改变「可见区域」的像素尺寸，不改变画布（文档）的像素尺寸；缩放比例不变时，画布上同一块区域仍对应同一逻辑范围，只是窗口大则看到更多内容、窗口小则相当于裁剪视图。

## 三、Miro（在线白板）

### 3.1 画布空间 vs 屏幕空间

- **画布空间（Board Space）**：  
  - **无限画布**，原点在画布**中心** `(0, 0)`。  
  - 对象位置一般表示其**中心**相对 board 中心的位置；单位在 SDK 中为 dp（设备无关像素）。  
  - Frame 内对象使用**相对 Frame 左上角**的坐标，需再叠加 Frame 相对 board 中心的位置才能得到画布坐标。
- **屏幕空间（Viewport）**：  
  - 当前可见矩形区域，在 SDK 中由 `viewport.get()` 返回：`x, y` 为视口**左上角**相对画布中心 `(0,0)` 的位置，`width, height` 为视口宽高（dp）。  
  - 视口中心可计算为：`(viewport.x + width/2, viewport.y + height/2)`。

因此：**画布空间 = 以 board 中心为原点的无限平面；屏幕空间 = 该平面上的一个矩形窗口（viewport）**。

### 3.2 缩放视图（Zoom）

- **操作**：  
  - 键盘：Cmd/Ctrl + +/-。  
  - 触控板：双指捏合缩放；部分模式下双指滑动为平移，需配合「导航模式」设置。  
  - 鼠标：滚轮默认多为缩放（依导航模式而定）。
- **范围**：SDK 中 `setZoom` 支持约 **1%～400%**（0.01～4）。  
- **行为**：以视口中心或手势中心缩放；缩放改变的是「画布单位与屏幕 dp 的比值」，不改变画布上对象的逻辑坐标。

### 3.3 多选/单卡缩放（Transform）

- **多选**：框选或 Shift 多选后，可整体移动、缩放、旋转；对象间相对位置与比例会保持。  
- **单对象**：选中后拖拽手柄缩放/旋转，支持对齐、分布等。  
- 坐标均在**画布空间**（board 中心为原点）；缩放/旋转后位置与变换由 Miro 内部存储，通过 SDK 读写时仍为画布坐标。

### 3.4 调整窗口（Resize）

- **浏览器窗口**：用户改变浏览器窗口或侧栏时，可见区域改变，Miro 会更新 **viewport 的 width/height**；`viewport.get()` 的 `x, y, width, height` 会随之变化。  
- **行为**：  
  - 一般不会在 Resize 时自动改 zoom level；相当于「窗口变大则看到更多画布，窗口变小则看到更少」。  
  - 若内容过小（如 zoom 低于 1%），用户可全选后整体放大对象，以在视觉上「放大内容」而非仅改视图 zoom。  
- **SDK**：`viewport.set({ viewport: { x, y, width, height } })` 可同时改位置与尺寸，用于适配或动画；实际尺寸会受屏幕、导航栏等影响，与传入值可能有出入。

## 四、PureRef（参考图/看板）

### 4.1 画布空间 vs 屏幕空间

- **画布空间（Canvas / Scene）**：  
  - 画布为窗口内浅色背景区域，**随内容扩展**以容纳所有图片；有「优化画布」使画布紧贴图片。  
  - 官方手册中「Reset camera」将相机恢复到默认位置 **(0, 0)**，可推断画布有固定原点（如中心或左上），对象位置在该逻辑空间中。  
  - 图片的位置、缩放、旋转等都在此逻辑空间内。
- **屏幕空间**：  
  - 即 PureRef **窗口**内可见区域；通过「相机」的平移 + 缩放，将画布空间投影到窗口。  
  - 与 DeckRef 类似：**屏幕坐标 = 窗口中心（或锚点）+ scale × (画布坐标 - offset)**。

### 4.2 缩放视图（Zoom）

- **操作**：  
  - **滚轮**：直接缩放。  
  - **Z + 左键拖拽**：按住 Z 并移动光标缩放。  
  - **Ctrl+0 / ⌘+0**：重置缩放到 100%。  
- **行为**：以光标或视图中心缩放，保持「指针下的画布点」在屏幕上的位置稳定（与 DeckRef、Photoshop 一致）。  
- 触控板：双指捏合缩放；**Ctrl/⌘ + 双指滑动**可模拟滚轮缩放。

### 4.3 多选/单卡缩放（Transform）

- **单图**：选中后可拖动、缩放、旋转；缩放范围约 30%～500%（与 DeckRef 类似），松手后保留。  
- **多选**：可多选后一起移动/缩放；行为未在公开文档中细述，通常为整体变换。  
- 所有变换都在**画布空间**中；保存/加载场景会持久化位置与缩放。

### 4.4 调整窗口（Resize）

- **操作**：拖拽窗口边或角调整大小；可设置「调整边框宽度」便于抓取。  
- **关键设置：「Scale scene on window resize」**  
  - **开启**：窗口 Resize 时，**画布缩放（zoom）随窗口尺寸联动**，使「当前可见内容」尽量保持相同的视觉范围，相当于用 zoom 补偿窗口尺寸变化（类似 DeckRef 画板模式的 offset 补偿思路，但 PureRef 用缩放补偿）。  
  - **关闭**：zoom 不变，窗口变大则看到更多画布，变小则相当于裁剪视图（与 Miro 默认行为接近）。  
- **Resize to selection**：可将窗口 Resize 到「适应选中对象」或「适应全部图片」，相当于一次性的「窗口 + 视口」适配。

## 五、对比小结

| 维度 | Chrome | Photoshop | Miro | PureRef |
|------|--------|-----------|------|---------|
| **画布空间** | 文档内容（page/document），CSS 像素 | 文档像素网格，图层/选区在此 | 无限画布，原点在中心 (0,0)，dp | 画布随内容扩展，有 (0,0) 相机原点 |
| **屏幕空间** | Visual Viewport（含 scale） | 文档窗口可见区域 = 画布矩形×缩放 | Viewport 矩形，相对 board 中心 | 窗口内可见区域，由相机 offset+scale 决定 |
| **Zoom 中心** | 由手势/焦点决定 | 点击/拖拽中心或指针 | 视口中心或手势 | 指针或 Z+拖拽 |
| **Zoom 后平移** | 可滚动/平移 | ＞100% 可平移，≤100% 且适应窗口时锁定 | 可自由平移 | 可自由平移（Alt/中键） |
| **Transform** | 由页面内应用自实现 | 多选共用一个变换框；无「按各自中心缩放」 | 多选整体变换，画布坐标 | 单图/多选可缩放旋转，画布空间 |
| **Resize 时** | Layout/Visual viewport 依平台变化 | 仅改可见区域；可选「缩放时调整窗口」 | 视口尺寸变，zoom 不变 | **可选**「Scale scene on window resize」用 zoom 补偿 |

## 六、对 DeckRef 的参考要点

1. **画布原点与屏幕中心**  
   - Miro、PureRef 都采用「画布中心或固定原点 + 视口/相机」的模型，与 DeckRef 的 `screen_center` + `view_offset` + `view_scale` 一致；保持「画布空间—屏幕空间」严格分离有利于后续扩展。

2. **Resize 补偿策略**  
   - **PureRef**：提供「Scale scene on window resize」用**缩放**补偿窗口变化，使「看到的内容」大致不变。  
   - **DeckRef 画板模式**：当前用 **offset 补偿**（保持画布中心对准新窗口中心），缩放不变。两种思路都可接受，取决于产品更强调「视觉范围不变」还是「缩放倍率不变」；文档 [CHUANGKOU_CANVAS_INTERACTION.md](CHUANGKOU_CANVAS_INTERACTION.md) 已明确当前为 offset 补偿。

3. **Zoom 以指针为中心**  
   - Photoshop（Scrubby Zoom）、PureRef（滚轮/Z+拖）、DeckRef 均采用「指针下的点不动」的缩放逻辑，便于精确查看局部，建议保持。

4. **多选 Transform**  
   - Photoshop 多选共用一个变换框；Miro/PureRef 为整体变换。DeckRef 当前以单卡拿起+缩放为主，若未来支持多选，可参考「整体变换框 + 画布坐标」的实现方式。
