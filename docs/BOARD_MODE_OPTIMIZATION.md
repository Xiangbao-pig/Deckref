# 画板模式优化文档（PS 式窗口逻辑）

本文档单独约定**画板模式**的窗口与画布理念，使其与 **Photoshop 的窗口逻辑**对齐：窗口是「取景框」，画布与元素在逻辑上固定，窗口变化时仅**裁剪区域（Clip）**变化，不触发重排（Reflow）与重绘（Repaint）。  
实现时以本文为准；与 [CHUANGKOU_CANVAS_INTERACTION.md](CHUANGKOU_CANVAS_INTERACTION.md) 冲突处，画板模式以本文优先。

**参考版本**：上述逻辑与 **Adobe Photoshop 2025**（含 26.x 系列）的文档窗口行为一致。PS 2025 未改变「窗口 = 取景框、画布（文档）尺寸与图层位置固定、仅视口/缩放随用户操作变化」的核心模型；Canvas Size（图像 → 画布大小）仍只改变文档区域，不因窗口 Resize 而重排内容。若需针对某小版本（如 26.10）的细节差异，可查阅 [Adobe Photoshop 发行说明](https://helpx.adobe.com/photoshop/using/whats-new/whats-new-in-adobe-photoshop-on-desktop.html)。

---

## 一、理念：窗口 = 取景框

- **Photoshop 的类比**（含 2025）：文档窗口像一个「取景框」。拉大窗口时，你只是看到了**画布上更多的区域**；画布（Canvas / 文档）的尺寸和图片（图层）的位置（以像素/逻辑单位计）是**固定**的。
- **DeckRef 画板模式**应遵循同一逻辑：
  - **窗口变大** → 取景框变大，看到更多画布区域；
  - **窗口变小** → 取景框变小，看到更少画布区域；
  - **画布尺寸**、**元素位置**、**元素间距**（绝对像素/逻辑值）**不因窗口变化而改变**，除非用户主动操作（平移、缩放视图、移动/缩放卡片）。

---

## 二、核心原则（窗口变化时）

当 DeckRef 的**窗口尺寸**（内容区 `stack_rect` / `last_stack_size`）发生变化时，**仅**以下成立：

| 项目 | 行为 |
|------|------|
| **内容尺寸** | 保持不变（视图缩放比例 `board_view_scale` 不变，除非用户手动滚轮缩放）。 |
| **元素位置与间距** | 以画布空间**绝对像素/逻辑单位**计，不变；不因窗口变大变小而重新缩放或重排。 |
| **坐标原点** | 默认为**画布左上角**（见第三节）。 |
| **触发机制** | **仅裁剪区域（Clip / Viewport）变化**：可见的「画布矩形」随窗口变大而变大、随窗口变小而变小；**不触发 Reflow（重排）**，**不触发 Repaint（重绘）**。 |

### 2.1 不触发 Reflow（重排）

- **含义**：不因窗口 Resize 而重新计算布局、不改变任何卡片的画布坐标或显示缩放、不调用「阵列」「一览」或任何会改写 `board_saved_world_pos` / `display_scale` 的逻辑。
- **当前实现的偏差**：若存在按「当前内容区尺寸 / 参考尺寸」对保存位置与缩放做等比缩放的逻辑（如 `board_scale_u` × 保存坐标），则窗口 Resize 会间接改变元素在画布上的表现，等价于 Reflow。画板模式优化后应**取消**此类随窗口尺寸变化的缩放，使画布内位置与缩放仅由用户操作与布局文件决定。

### 2.2 不触发 Repaint（重绘）

- **含义**：不因 Resize 而触发「布局失效 → 重新排版 → 再绘制」的链路。仅因「可见区域（Clip）变了」而多画或少画一部分画布，属于正常的视口绘制，不算 Reflow 触发的 Repaint。
- **实践**：Resize 时只更新视口/裁剪参数，不标记布局脏、不重新应用布局或重算卡片位置/缩放。

## 三、坐标系：画布原点与画布尺寸

### 3.1 画布原点

- **默认**：**画布左上角**为原点 `(0, 0)`。
- **方向**：X 向右为正，Y 向下为正（与常见 2D 画布、PS 文档一致）。
- **与当前实现的衔接**：若当前实现以「内容区中心」为屏幕锚点、用 `board_view_offset` 表示平移，可保留该视口模型，但在**画布空间**中明确定义：所有保存与计算使用**相对画布左上角**的坐标；必要时在布局文件或内存中维护「画布尺寸」与「视口在画布中的矩形」，以便 Resize 时只改视口不缩放内容。

### 3.2 画布尺寸（固定）

- 画布在逻辑上具有**固定宽高**（例如在首次保存布局或进入画板时确定），不随窗口 Resize 改变。
- **建议**：在 `.deckref_layout.json` 中增加 `canvas_size: [w, h]`（或沿用 `reference_available_size` 语义为「画布固定尺寸」且**仅用于定义画布范围，不参与 Resize 时的缩放**）。卡片位置与缩放均以该固定画布为参考，单位与画布一致（逻辑像素/点）。

### 3.3 视口（取景框）与 Clip

- **视口**：在画布上可见的矩形区域，由「视口在画布中的位置 + 视口在屏幕上的像素尺寸」决定。
- **Resize 时**：仅「视口在屏幕上的像素尺寸」随内容区变化；视口在画布中的位置可按现有策略做**可选**补偿（例如保持「原先在屏幕中心的那一点仍在中心」），但**不改变画布尺寸、不缩放画布内任何坐标或缩放值**。
- **Clip**：渲染时仅绘制落在当前视口内的内容；Resize 后 Clip 随之变化，只是「看到更多/更少画布」，不触发对画布数据或布局的重新计算。

## 四、与当前实现的差异（改造要点）

| 项目 | 当前实现（简述） | 目标（PS 式） |
|------|------------------|----------------|
| 画布与窗口关系 | `layout_reference_size` 与 `last_stack_size` 算出 `board_scale_u`，对保存的 position/scale 按比例缩放后再显示；窗口变大则整体「放大」显示。 | 画布固定尺寸；保存的 position/scale 为画布空间绝对值，**不**随窗口尺寸缩放；窗口变大仅表示取景框变大，看到更多画布。 |
| 坐标原点 | 变换以内容区中心为锚点，`board_view_offset` 为平移；未显式声明画布左上角为原点。 | 画布空间显式以**左上角为原点**；视口/变换可继续用中心锚点实现，但逻辑上等价于「在固定画布上滑动取景框」。 |
| Resize 时 | 每帧用 `last_board_screen_center` 与当前 `screen_center` 的差补偿 `board_view_offset`，避免画布「跳动」；但 `board_scale_u` 随 `last_stack_size` 变化，导致内容等效于被缩放（Reflow）。 | Resize 时**不**用 `last_stack_size` 去缩放任何画布坐标或缩放值；仅更新视口/Clip 与可选 offset 补偿；**不**引入 `board_scale_u` 对位置/缩放的缩放。 |
| 布局加载 | 若存在 `reference_available_size`，加载后设 `layout_reference_size`，后续用 `board_scale_u` 映射到当前窗口。 | 布局中的位置与缩放视为**画布绝对值**；`reference_available_size` 仅作为「画布固定尺寸」记录，**不**参与 Resize 时的缩放；新布局可写入 `canvas_size` 或等价字段。 |

## 五、实现要点与后续改造建议

1. **固定画布，取消 Resize 带来的缩放**
   - 画板模式下，进入某目录并加载布局后，将「画布尺寸」固定（例如 = 布局中的 `reference_available_size` 或新的 `canvas_size`）；卡片位置与缩放直接使用布局中的值，不再用 `board_scale_u`（或令 `board_scale_u = 1.0`）参与显示与保存。
   - 窗口 Resize 时：**不**根据 `last_stack_size` 重算 `board_scale_u`，**不**对 `board_saved_world_pos` / `display_scale` 做任何缩放。

2. **仅 Clip / 视口随窗口变化**
   - 内容区尺寸 `last_stack_size` 变化时，仅更新「可见区域」的尺寸与裁剪；视口在画布中的位置可按现有方式做 offset 补偿（保持中心不跳），但**不**改变任何卡片在画布空间的数据。

3. **画布原点为左上角**
   - 在布局与内部数据结构中，统一使用「相对画布左上角」的坐标与尺寸；若当前保存的是「相对中心」或其它参考，需在文档与实现中给出换算关系，并在新布局或迁移时逐步统一为左上角原点。

4. **不触发 Reflow / Repaint**
   - Resize 路径中不调用会修改卡片位置/缩放/顺序的逻辑（如 grid_arrange、一览、或任何按窗口尺寸重算 layout 的代码）；不因 Resize 设置「布局脏」或强制重新应用布局。

5. **与 CHUANGKOU_CANVAS_INTERACTION 的同步**
   - 画板模式以本文为准后，在 [CHUANGKOU_CANVAS_INTERACTION.md](CHUANGKOU_CANVAS_INTERACTION.md) 中更新「画板模式」相关小节：明确画布固定、原点左上角、Resize 仅改 Clip、不做 `board_scale_u` 缩放，并保留与默认/灵感模式的差异说明。

---

## 六、小结

- **理念**：画板模式窗口 = PS 式取景框；拉大窗口 = 看到更多画布，画布与元素不动。
- **窗口变化时**：内容尺寸（视图缩放）不变（除非用户手动缩放），元素位置与间距（绝对像素/逻辑值）不变，坐标原点为画布左上角，**仅裁剪区域（Clip）变**，**不触发 Reflow，不触发 Repaint**。
- **改造重点**：固定画布尺寸、取消 `board_scale_u` 在 Resize 时对位置/缩放的缩放、统一画布原点为左上角、Resize 路径仅更新视口/Clip 与可选 offset 补偿。
